## 四、核心交付：分阶段推理封装 (`scripts/inference.py`)

### 4.1 设计原则

1. **当前 MVP 只生成 Shape，不启用未下载的文生图和纹理模型**
2. **透明 PNG 保留 alpha；普通 RGB 图片可选择调用 rembg**
3. **每个阶段使用 `try/finally`，成功或异常都会解除引用、迁回 CPU 并清理 CUDA 缓存**
4. **使用 `from_single_file()` 直接从本地文件加载，不依赖 HuggingFace Hub 网络**
5. **启用 `enable_model_cpu_offload()` 降低峰值显存（8GB VRAM 适配关键）**
6. **通过固定 `seed` 支持同配置复现实验**

### 4.2 API 接口一览

```python
from scripts.inference import Hunyuan3DGenerator

gen = Hunyuan3DGenerator(
    model_dir='D:/AI文创3D打印/models',  # 模型根目录
    variant='turbo',                       # 'turbo' | 'standard'
)

# ── 当前核心推理 ──
mesh = gen.generate_shape(
    image,
    seed=0,
    remove_background=False,                # 透明 PNG 不需要抠图
)                                             # 图→3D 形状（加载→推理→卸载）

# ── 格式导出 ──
gen.export_stl(mesh, 'output.stl')          # STL（无纹理，打印前仍需 DFM/切片验证）
gen.export_obj(mesh, 'output.obj')          # OBJ
gen.export_glb(mesh, 'output.glb')          # GLB（当前无纹理）

# ── 一站式接口 ──
gen.image_to_3d(image, export_stl=...,      # 图生3D全流程
                export_glb=..., with_texture=False)

# ── 状态查询 ──
gen.memory_status()                         # 查看显存+模型加载状态
```

### 4.3 generate_shape 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `image` | 必填 | 输入图片路径或 PIL.Image |
| `num_inference_steps` | 按 variant | turbo 25，standard 50；可显式覆盖 |
| `guidance_scale` | 5.0 | CFG 引导强度 |
| `octree_resolution` | 256 | 网格提取分辨率（越高越精细，越耗显存） |
| `num_chunks` | 5000 | MC 分块数（降低可减少峰值显存） |
| `seed` | 0 | 随机种子，用于复现实验 |
| `remove_background` | `False` | RGB 图片是否调用 rembg；透明 PNG 不需要开启 |

### 4.4 显存管理机制

```
generate_shape():
  1. _load_shape_pipeline()      → 加载 Shape 模型 + CPU Offload
  2. pipeline(image)             → 推理生成网格
  3. finally                     → 无论成功/异常都执行卸载
  4. _unload_shape_pipeline()    → 移除 hook + 迁回 CPU + gc + empty_cache
  5. return mesh                 → 返回 trimesh 对象

generate_texture():  （保留的后续纹理分支，模型未下载、当前未验收）
  1. _load_tex_pipeline()        → 检测 Shape 是否已卸载，未卸载则报错
  2. pipeline(mesh, image)       → 生成纹理
  3. _unload_tex_pipeline()      → 释放显存
  4. return textured_mesh

memory_status() 可随时检查：
  - VRAM 使用量
  - Shape pipeline 是否加载
  - Texture pipeline 是否加载
  - 是否出现双模型共存（!! 警告 !!）
```

### 6.2 DFM 检查项（6 大类 23 项）

#### 前置处理（P0 阻断级）

- [x] **P0 坐标/单位标准化**：Hunyuan 归一化输出按 `normalized_up_axis: y` 转成打印坐标 Z-up，再按旋转后的真实高度定高并落到 Z=0；毫米模型保持输入朝向与尺寸；自动模式遇到小尺寸歧义返回 `INCOMPLETE`，不擅自放大
- [x] **P1 底面平台校验**：只统计共面底部三角面的真实投影；点/边接触不再被最低点凸包误判为大面积接触
- [x] **P2 外框超限**：AABB 包围盒超过打印机成型尺寸时阻断
- [x] **P3 静态稳定性**：重心 XY 投影是否位于支撑凸包安全裕量内；不足则有倾倒风险，由 P1 底座生成解决

#### 几何拓扑（G0 阻断级 — 切片崩溃致命缺陷）

- [x] **G1 水密性**：`trimesh.is_watertight`
- [x] **G2 自相交**：pymeshlab 自相交面选择；超过同步面数上限时返回 `UNKNOWN`，待服务器异步检测
- [x] **G3 非流形边**：统计 `edges_unique_inverse` 中被 ≥3 个面共用的边
- [x] **G4 翻转法向**：`is_winding_consistent` + 水密网格有符号体积
- [x] **G5 重复/零面积面片**：面顶点索引排序去重 + 尺度相关退化面积容差
- [x] **G6 孤立游离碎面**：检测小碎片，并阻断任何未接触平台的悬空独立分量

#### 壁厚与结构（W 级 — 警告/阻断按工艺可配置）

- [x] **W1 最小壁厚（基础估算）**：确定性表面采样 + 向内射线，按 `index_ray` 配对并取最近命中；仍需复杂薄壳真值集验证
- [ ] **W2 最小特征尺寸**：骨架分析 + SDF 检测细剑尖/飘带末梢等脆弱结构
- [ ] **W3 拉丝/细长比**：截面分析柱体高度/最小宽度 > 10~15
- [ ] **W4 镂空点阵壁厚**：SDF 体素化度两实体面间距，精准定位薄弱点

#### 空腔检测（C 级）

- [ ] **C1 封闭空腔**：SDF 体素化 → 3D 连通域 → 排除触及边界的半开放凹槽 → 输出空腔坐标/体积
- [ ] **C2 排液孔**（光固化）：中空模型无排液孔 → "吸力杯"效应，打印失败

#### 悬垂与支撑（S 级）

- [x] **S1 悬垂角**：只统计 `normal_z < -cos(临界角)` 的朝下面，排除平台底面并按面积占比判定；竖直侧壁不再误报
- [ ] **S2 桥接检测**：水平悬空两点间跨度 > 15mm → 拉丝风险（FDM 独有）
- [ ] **S3 悬空孤岛**：分层切片 + 连通比对，某层新出现轮廓下方无对应 → 坍塌
- [ ] **S4 最小支撑接触面积**：悬垂面投影面积累加 < 3mm² → 支撑脱落

### 6.3 分层质检流水线

```
第一级：快速粗筛（同步；G2 耗时随面数增长）
  P0 标准化 → P1 平台 → P2 外框 → G1~G6 拓扑 → S1 悬垂角
  FAIL 或阻断项 UNKNOWN → 不进精检；高面数模型转服务器异步任务

第二级：精细精检
  当前可靠基础项：W1 壁厚抽样、D2 装配间隙
  W2~W4、C1~C2、S2~S5、D1、D3 在真值测试验收前返回 UNKNOWN/N/A，不计分

第三级：修复 + 仿真
  独立工作进程执行底座/碎片/pymeshlab 修复（单阶段硬超时）→ 复检闭环
  → 仅 PASS 报告进入格式导出/slice_prepared()
  → CuraEngine 切片 → 解析层数、时间、耗材、刀路边界与错误/警告
```

### 6.4 分级修复策略

| 级别 | 操作 | 工具 | 状态 |
|:--:|------|------|:--:|
| 底座 | P1/P3 失败时自动生成适配底座（disc/block/auto），多级布尔融合后复检 | trimesh + pymeshlab | ✅ 已实现 |
| 清理 | G6 失败时自动删除孤立/悬浮小碎片，AABB/距离保护嵌入配件 | trimesh split + ProximityQuery | ✅ 已实现 |
| 轻量 | 合并重叠顶点、统一法向、删除零面积/重复三角面、清理孤立顶点 | pymeshlab | ✅ 已实现 |
| 中度 | 填补破洞、修复非流形边/顶点 | pymeshlab | ✅ 已实现 |
| 中度 | 黑盒修复兜底 | MeshFix CLI | ✅ 已集成 |
| 重度 | V-HACD 重网格化、网格简化 | trimesh / MeshFix | 🔲 预留接口 |
| 兜底 | 无法修复 → 退回生成阶段换 seed 重新生成 | 自研调度 | ✅ 已实现 |

**修复闭环流程**：`repair_and_recheck(mesh, checker)` →
初始快速检查 → UNKNOWN 转异步/人工复核；按失败码依次执行：
→ [P1/P3] 底座自动生成 → 复检
→ [G6] 碎片自动清理 → 复检
→ [碎片清理后仍有 P1/P3] 重试底座
→ [G4/G5] 轻量修复 → 复检
→ [G1/G2/G3] 中度修复 → 复检
→ [拓扑修复后仍有 G6] 追加碎片清理
→ [拓扑修复后仍有 P1/P3] 重试底座
→ 其他失败项安全停止并返回 FALLBACK

每类自动化操作最多执行 2 次（`pedestal_attempts < 2`、`fragment_attempts < 2`），
防止无限循环。

底座、碎片清理及 pymeshlab 轻量/中度修复默认通过 `python -m dfm.repair_worker` 在独立子进程中执行，单阶段硬时限由 `repair.repair_stage_timeout_seconds` 配置（本地/服务器可分别调整）。超时会强制结束当前工作进程并返回阶段前的最后有效网格；`RepairResult.timed_out`、`timeout_stage`、`resume_from_stage` 记录可恢复位置，`progress_callback` 提供结构化阶段进度。MeshFix 使用它自身的 CLI 超时，避免嵌套进程留下孤儿进程。

所有闭环候选网格在提交前都会与阶段前快速报告比较：FAIL 数量不能增加、总分不能下降、不能新增 UNKNOWN。未通过时记录事务性回滚动作并继续使用旧网格；拓扑候选回滚后立即停止派生修复，避免 B01 曾出现的 70→50 分退化和无效的中度/底座重试。

> 修复完成后必须重新跑全部检测（检查→修复→复检闭环），确认缺陷消除且无新增问题。

**prepared_mesh 导出链路（已完成）**：正式入口 `image_to_prepared_3d()` 使用最后一次快速复检报告中的同一个毫米网格作为返回、STL/GLB 导出和后续切片对象；旧 `image_to_printable_3d()` 仅作为兼容别名。Hunyuan 原始 Y-up 网格先转为打印坐标 Z-up，再按目标高度缩放和落台；这只是固定坐标约定转换，不是基于悬垂/支撑代价的自动朝向优化。非 `PASS` 状态默认不写文件，诊断导出必须显式使用 `allow_failed_export=True`。修复器复用检查规则并以 `input_units='mm'` 接收 `prepared_mesh`，小尺寸毫米模型不会被二次判成单位不明确。当前返回的 `ready_for_slicing=True` 只表示快速层通过，`printable_verified` 固定为 `False`，仍须精检和目标打印机 profile 验证。

### 6.5 CuraEngine 切片仿真（基础版已完成）

- Windows 5.13.0 运行时放在 `.cache/tools/curaengine/5.13.0/windows-x64/`，由 `tools/curaengine/runtime-manifest.json` 记录来源、平台和文件 SHA-256；未把二进制或完整 Cura 安装目录提交 Git
- `CuraSlicer` 按“显式参数 → 环境变量 → 项目缓存 → `PATH`”发现引擎和资源，加载 `fdmprinter` + `fdmextruder` 定义
- 业务入口 `slice_prepared(report, ...)` 默认只接受 `PASS` 报告并使用毫米制 `prepared_mesh`；`allow_failed=True` 仅供诊断，底层 `slice()` 也拒绝 `normalized` / `auto` 输入
- `SliceResult` 输出成功状态、G-code 路径/大小、层数/层高、耗材长度/质量、时间、刀路边界、挤出移动数、引擎版本以及错误/警告
- G-code 解析采用最终 `TIME_ELAPSED`，耗材按 E 轴状态计算并扣除回抽；空文件、无有效层、无有效挤出、无刀路边界都会判失败
- 当前 profile 是通用单挤出机 FDM 仿真配置，结果固定标记 `simulation_only=True`，尚未纳入可打印性评分，也不能直接发送打印机

| 验收样本 | DFM/调用方式 | 层数 | 估算时间 | 估算耗材 | 验收结论 |
|----------|--------------|----:|---------:|---------:|----------|
| 20 mm 立方体 | 毫米输入，底层接口冒烟 | 100 | 25.08 min | 2001.56 mm / 5.97 g | 运行时、命令栈、输出与解析通过 |
| 当前图生 3D 冒烟模型 | DFM `FAIL`（P1/G5），`allow_failed=True` 诊断 | 500 | 1354.52 min | 129562.72 mm / 386.427 g | 仅证明可被引擎切片；默认链路已阻断 |

下一步是为比赛使用的具体打印机、喷嘴、材料和质量档建立 profile 真值，并在服务器固定 Linux x64 运行时；在此之前不能把通用仿真结果描述为“可直接打印”。

### 6.6 可打印性评分

| 维度 | 权重 | 评分逻辑 |
|------|:--:|------|
| 水密/拓扑 | 25% | 水密+无非流形=满分，每项缺陷扣分 |
| 壁厚 | 25% | 最小壁厚/目标壁厚 × 100，< 阈值直接 0 |
| 悬垂/支撑 | 20% | 悬垂面占比越少分越高，> 30% 面积 ≤ 60 |
| 尺寸合规 | 15% | 外框/内孔/间隙均合规 = 满分 |
| 特征/结构 | 10% | 最小特征尺寸/喷嘴直径 × 100 |
| 空腔 | 5% | 无封闭空腔或有排液孔 = 满分 |

## 八、已知问题 & 注意事项

1. **当前只做图生 3D**：文生图模型未下载，`text_to_3d` 入口已暂时移除
