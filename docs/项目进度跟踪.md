## 四、核心交付：分阶段推理封装 (`scripts/inference.py`)

### 4.1 设计原则

1. **当前 MVP 只生成 Shape，不启用未下载的文生图和纹理模型**
2. **透明 PNG 保留 alpha；普通 RGB 图片可选择调用 rembg**
3. **每个阶段使用 `try/finally`，成功或异常都会解除引用、迁回 CPU 并清理 CUDA 缓存**
4. **使用 `from_single_file()` 直接从本地文件加载，不依赖 HuggingFace Hub 网络**
5. **启用 `enable_model_cpu_offload()` 降低峰值显存（8GB VRAM 适配关键）**
6. **通过固定 `seed` 支持同配置复现实验**

### 4.2 API 接口一览

```python
from scripts.inference import Hunyuan3DGenerator

gen = Hunyuan3DGenerator(
    model_dir='D:/AI文创3D打印/models',  # 模型根目录
    variant='turbo',                       # 'turbo' | 'standard'
)

# ── 当前核心推理 ──
mesh = gen.generate_shape(
    image,
    seed=0,
    remove_background=False,                # 透明 PNG 不需要抠图
)                                             # 图→3D 形状（加载→推理→卸载）

# ── 格式导出 ──
gen.export_stl(mesh, 'output.stl')          # STL（无纹理，打印前仍需 DFM/切片验证）
gen.export_obj(mesh, 'output.obj')          # OBJ
gen.export_glb(mesh, 'output.glb')          # GLB（当前无纹理）

# ── 一站式接口 ──
gen.image_to_3d(image, export_stl=...,      # 图生3D全流程
                export_glb=..., with_texture=False)

# ── 状态查询 ──
gen.memory_status()                         # 查看显存+模型加载状态
```

### 4.3 generate_shape 参数说明

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `image` | 必填 | 输入图片路径或 PIL.Image |
| `num_inference_steps` | 按 variant | turbo 25，standard 50；可显式覆盖 |
| `guidance_scale` | 5.0 | CFG 引导强度 |
| `octree_resolution` | 256 | 网格提取分辨率（越高越精细，越耗显存） |
| `num_chunks` | 5000 | MC 分块数（降低可减少峰值显存） |
| `seed` | 0 | 随机种子，用于复现实验 |
| `remove_background` | `False` | RGB 图片是否调用 rembg；透明 PNG 不需要开启 |

### 4.4 显存管理机制

```
generate_shape():
  1. _load_shape_pipeline()      → 加载 Shape 模型 + CPU Offload
  2. pipeline(image)             → 推理生成网格
  3. finally                     → 无论成功/异常都执行卸载
  4. _unload_shape_pipeline()    → 移除 hook + 迁回 CPU + gc + empty_cache
  5. return mesh                 → 返回 trimesh 对象

generate_texture():  （保留的后续纹理分支，模型未下载、当前未验收）
  1. _load_tex_pipeline()        → 检测 Shape 是否已卸载，未卸载则报错
  2. pipeline(mesh, image)       → 生成纹理
  3. _unload_tex_pipeline()      → 释放显存
  4. return textured_mesh

memory_status() 可随时检查：
  - VRAM 使用量
  - Shape pipeline 是否加载
  - Texture pipeline 是否加载
  - 是否出现双模型共存（!! 警告 !!）
```

> 这是低步数、低分辨率的链路冒烟结果，只证明代码能真实生成和导出，
> 不代表比赛质量，也不代表模型已通过壁厚、尺寸、悬垂、自相交或切片检查。

### 5.2 本轮修复的真实运行阻断

1. 上游自定义 pipeline 缺少 CPU Offload 所需的 `components` 属性：已在项目封装层补齐，不修改官方源码；
2. CPU Offload 后采样张量落在 CPU、模型输出落在 CUDA：已恢复 pipeline 执行设备并使用同设备随机数生成器；
3. 透明 PNG alpha 被转换为 RGB 丢失：已保留 RGBA；
4. 推理异常跳过卸载：已使用 `try/finally`，实测失败后显存可回收；
5. 文生 3D 未下载却暴露入口：当前已移除 `text_to_3d`。

## 八、已知问题 & 注意事项

1. **当前只做图生 3D**：文生图模型未下载，`text_to_3d` 入口已暂时移除
2. **纹理模型未下载**：当前支持无纹理 STL/OBJ/GLB 导出，GLB 彩色导出尚未验收
3. **当前产物仅为冒烟质量**：完整步数、较高分辨率和 10+ 测试图尚未验证
4. **RGB 背景**：默认不自动抠图，优先使用透明 PNG；需要时传入 `remove_background=True`
5. **RTX 5060 架构兼容性**：需 PyTorch with CUDA 12.8+（已处理，不支持 cu124 旧版 PyTorch）
6. **首次推理可能较慢**：CUDA kernel 编译有预热开销
7. **CPU Offload 依赖 `accelerate` 包**：已安装，不可卸载
8. **依赖警告**：当前 `requests` 会提示缺少字符检测依赖，不影响本地 Shape 冒烟测试，后续整理依赖清单时处理
9. **原始代码未修改**：`Hunyuan3D-2-main/` 保持原样，所有项目改动在 `scripts/inference.py` 中
